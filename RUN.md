# Запуск «ЛистОК» / Worksheet Creator

Инструкция относится к текущему исходному коду и локальному адаптеру run_local.py. Адаптер не меняет backend: он исправляет маршрутизацию API для браузера, блокирует диагностическую выдачу частей ключа и запускает сервер только на 127.0.0.1.

## Что требуется

- Python. Dockerfile использует 3.11; локальные проверки маршрутов выполнены на 3.12.14. Полный цикл генерации на этих окружениях пока не проверен.
- Зависимости из корневого requirements.txt.
- Действующий ключ авторизации GigaChat с подходящим scope для реальной генерации.
- pdflatex в PATH и TeX-пакеты для русского языка, математики, TikZ и multicol.
- Интернет для GigaChat. Шрифты и значки веб-интерфейса также загружаются с внешних ресурсов.

Node.js и Marp текущему приложению не нужны.

## 1. Подготовка каталога

В корне проекта должны находиться app/, bot/, requirements.txt и run_local.py. run_local.py входит в пакет конкурсной адаптации.

Если исходники уже распакованы, откройте терминал в их корне. При получении из GitHub используйте:

~~~bash
git clone https://github.com/pavelneumoin/worksheet-creator.git
cd worksheet-creator
~~~

Если используете более ранний снимок Worksheet Creator без run_local.py, добавьте этот файл из пакета адаптации в корень.

## 2. Python-зависимости

Windows PowerShell:

~~~powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
~~~

Linux/macOS:

~~~bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
~~~

Активация окружения не требуется: команды ниже вызывают его Python напрямую. Для локального адаптера достаточно корневого requirements.txt. Gunicorn нужен для существующего Linux/Docker-развёртывания и входит в app/requirements.txt.

## 3. Окружение

| Переменная | Назначение |
|---|---|
| GIGACHAT_CREDENTIALS | Ключ авторизации GigaChat |
| GIGACHAT_SCOPE | Scope вашего ключа; задавайте явно |
| USE_CLOUD_LATEX | false для локального компилятора, true для внешней компиляции |
| TELEGRAM_BOT_TOKEN | Нужна только для отдельного Telegram-бота |

Пример для Windows PowerShell без записи ключа в историю команд:

~~~powershell
$worksheetSecret = Read-Host 'Ключ авторизации GigaChat' -AsSecureString
$env:GIGACHAT_CREDENTIALS = [System.Net.NetworkCredential]::new('', $worksheetSecret).Password
$env:GIGACHAT_SCOPE = 'GIGACHAT_API_PERS'
$env:USE_CLOUD_LATEX = 'false'
~~~

Для корпоративного ключа используйте соответствующее значение scope. В коде предусмотрено GIGACHAT_API_CORP, но подходящее значение определяется вашим доступом.

Пример для Bash:

~~~bash
read -r -s -p "Ключ авторизации GigaChat: " GIGACHAT_CREDENTIALS
export GIGACHAT_CREDENTIALS
export GIGACHAT_SCOPE=GIGACHAT_API_PERS
export USE_CLOUD_LATEX=false
~~~

Значения ключей не нужно записывать в README, презентацию или Git. Для backend задавайте окружение явно: сам app.py не вызывает load_dotenv(). Альтернатива — локальный app/backend/config.py на основе config.py.example; окружение имеет приоритет.

Без действующего ключа можно открыть интерфейс и проверить маршруты. Создание материалов через ИИ в таком режиме не работает.

## 4. Проверка TeX

~~~bash
pdflatex --version
~~~

Шаблон использует inputenc, fontenc T2A, babel/russian, amsmath, amssymb, mathtools, multicol, geometry, TikZ и xcolor. Набор Linux-пакетов, предусмотренный существующим Dockerfile:

~~~text
texlive-latex-base
texlive-fonts-recommended
texlive-latex-extra
texlive-lang-cyrillic
texlive-xetex
cm-super
lmodern
~~~

При отдельной пробной сборке копии шаблона на текущем компьютере MiKTeX сообщил об отсутствии `mathtools.sty`; пакеты автоматически не устанавливались, PDF не создан. До совместного полного теста нужно подготовить указанные TeX-зависимости. Наличие команды `pdflatex` само по себе ещё не означает, что все пакеты установлены.

USE_CLOUD_LATEX=false **не запрещает сетевую компиляцию**: если pdflatex не найден, текущий код автоматически обращается к внешнему компилятору. При true он делает это сразу. LaTeX-документ, включая тему, имя учителя и задания, передаётся внешнему сервису. Для демонстрации с локальной компиляцией сначала убедитесь, что pdflatex доступен.

## 5. Запуск веб-интерфейса

Windows:

~~~powershell
.\.venv\Scripts\python.exe run_local.py
~~~

Linux/macOS:

~~~bash
.venv/bin/python run_local.py
~~~

Откройте [http://127.0.0.1:3005](http://127.0.0.1:3005). Остановка — Ctrl+C.

Другой локальный порт:

~~~bash
python run_local.py --port 3015
~~~

Для адаптера, который лежит отдельно от исходников:

~~~bash
python run_local.py --repo-root /absolute/path/to/worksheet-creator
~~~

Используйте в этих командах Python вашего виртуального окружения. Адаптер всегда слушает 127.0.0.1, не включает debugger/reloader и не принимает параметр публичного host.

Обычный запуск python app/backend/app.py тоже использует порт 3005, но включает debug и оставляет несовпадение /worksheet-api/ и /api/. Для браузерной демонстрации используйте адаптер.

## 6. Первый сценарий

1. Введите тему рабочего листа и имя учителя, если оно нужно в шапке.
2. Выберите число задач на странице и 1 либо 2 колонки.
3. Загрузите чёткие PNG/JPEG с математическими заданиями. В текущем UI доступен GigaChat-Max.
4. Проверьте тело LaTeX в редакторе, особенно формулы и числа.
5. Нажмите «Сгенерировать PDF».
6. Откройте лист и отдельные ответы, если их удалось собрать. Проверьте оба документа перед печатью.
7. Для второго варианта выберите сложность и запустите генерацию. Проверка его условий и ответов остаётся обязанностью учителя.

Для начала используйте небольшой пример из нескольких задач. PDF в поле выбора разрешён, но его надёжная обработка не подтверждена. Вставка DOCX и отдельный сценарий генерации только по теме не реализованы.

Показанный в окне LaTeX — фрагмент тела документа. Чтобы собрать его вне приложения, понадобятся преамбула и макросы из app/backend/templates/default_worksheet.tex.

## 7. Telegram-бот

Это существующий альтернативный клиент, не интеграция MAX. Сначала запустите backend-адаптер на стандартном порту 3005: bot/handlers.py фиксирует этот адрес.

Задайте TELEGRAM_BOT_TOKEN в окружении. Бот также поддерживает локальный .env через python-dotenv.

Windows:

~~~powershell
.\.venv\Scripts\python.exe bot/bot.py
~~~

Linux/macOS:

~~~bash
.venv/bin/python bot/bot.py
~~~

Бот принимает фотографии, предлагает 1 или 2 колонки и отправляет PDF. Его маршрут проверки учителем пока менее полный, чем веб-редактор. Реальный запуск с Telegram в этой работе не проверялся.

## 8. Существующий Dockerfile

Сборка выполняется с контекстом app/, поскольку Dockerfile копирует backend и frontend относительно этого каталога:

~~~bash
docker build -f app/Dockerfile -t listok-prototype ./app
docker run --rm --name listok-prototype -p 127.0.0.1:3005:10000 --env GIGACHAT_CREDENTIALS --env GIGACHAT_SCOPE listok-prototype
~~~

Образ запускает Gunicorn на 10000 и включает TeX Live. Это рецепт исходного backend, а не проверенная новая сборка. Корневой run_local.py в этот образ автоматически не попадает. Поэтому:

- backend API находится по /api/;
- браузерный frontend всё ещё требует отображения /worksheet-api/ на /api/;
- блокировка debug-env из локального адаптера в исходном контейнере не действует;
- данные SQLite и созданные файлы без отдельного volume исчезнут после удаления контейнера.

Для текущей локальной демонстрации используйте раздел 5. Контейнеризацию адаптера, публичное развёртывание и полную проверку образа команда выполняет отдельным техническим этапом. Исторические deploy_nginx.py и fix_nginx.py не являются универсальными установщиками: они рассчитаны на прежний сервер.

## 9. API для проверки разработчиком

В локальном адаптере доступны оба префикса: /api/ и /worksheet-api/.

| Метод и путь | Данные | Результат |
|---|---|---|
| POST /api/process | multipart files; task_count, model | Тело LaTeX |
| POST /api/compile | JSON latex_code, topic, teacher_name, layout, is_variant2 | Ссылки на PDF и при наличии keys PDF |
| POST /api/generate_similar | form original_text, task_count, model, difficulty | Тело LaTeX второго варианта |
| GET /api/history | limit, по умолчанию 50 | Общая локальная история |
| GET /api/generated/имя-файла | Имя созданного файла | Файл |
| GET /api/debug-env | — | В адаптере заблокирован: 404 |

Для API-ошибок провайдера есть ограничение: текущий клиент иногда возвращает строку ошибки внутри latex_code с HTTP 200. «Текст распознан» в интерфейсе поэтому ещё не доказывает успешную обработку.

## 10. Что действительно проверено

В подготовленном адаптере прошли 11 проверок Flask test-client на временной копии репозитория:

- страница, script.js и style.css;
- история с обоими префиксами;
- пустые process/compile возвращают 400;
- диагностический endpoint с обоими префиксами возвращает 404;
- существующий PDF-fixture отдаётся с обоими префиксами.

Внешняя сеть была отключена, использован демонстрационный ключ. PDF-fixture взят из исходного репозитория. Новые PDF не компилировались. ИИ, Docker, Telegram, MAX, производительность и качество заданий пока не проверены.

## 11. Известные ограничения

Публичный многопользовательский запуск требует отдельной доработки: авторизации, раздельной истории, ограничения загрузок, изолированной TeX-сборки и устранения диагностической выдачи секретов в основном backend. Локальный адаптер закрывает только описанные проблемы маршрутизации и debug endpoint.

Если сборка PDF неуспешна, проверьте доступность pdflatex и log-файл в app/backend/static/generated. Не используйте app/backend/test_api.py как готовый безопасный тест: это исторический скрипт с локальным путём и печатью части ключа.

MAX и Marp не настраиваются переменными окружения текущей версии: соответствующих реализаций ещё нет.
