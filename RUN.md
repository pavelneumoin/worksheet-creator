# Локальный запуск «ЛистОК»

Инструкция относится к обновлённому локальному прототипу: математика и физика, редактируемый LaTeX, локальная PDF-сборка. Сначала можно проверить ручные примеры без ИИ, затем подключить свои фотографии через GigaChat.

## Что требуется

- Python и зависимости из корневого `requirements.txt`. Локальные проверки выполнены на Python 3.12.14; Dockerfile использует Python 3.11.
- MiKTeX или TeX Live с XeLaTeX либо pdfLaTeX и пакетами шаблона. На текущем компьютере проверен XeLaTeX из MiKTeX.
- Браузер. Node.js и Marp для текущего приложения не нужны.
- Для ИИ: доступ к GigaChat API, подходящие scope/модель и доверенные TLS-сертификаты.

## 1. Python-окружение

Откройте терминал в корне полученного проекта — рядом с `run_local.py`, `requirements.txt` и папкой `app`.

Windows PowerShell:

~~~powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
~~~

Linux/macOS:

~~~bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
~~~

Активация окружения не требуется. Команды ниже вызывают его Python напрямую. Если проект уже настроен, используйте существующую `.venv`, а не создавайте её повторно.

## 2. Настройка окружения

Без ИИ этот шаг можно пропустить: ручные примеры и PDF-сборка доступны при установленном TeX.

Для подключения ИИ скопируйте безопасный образец и заполните локальный `.env` в редакторе:

~~~powershell
Copy-Item -LiteralPath '.env.example' -Destination '.env'
~~~

Не выполняйте копирование поверх уже настроенного `.env`. Дополнительный `.env.sample` в пакете документации содержит те же основные настройки. Сам `.env`, `app/backend/config.py` и каталог `.local-certs/` исключены из Git; действующие ключи не должны попадать в презентацию, архив исходников или журнал команд.

| Переменная | Значение |
|---|---|
| `GIGACHAT_CREDENTIALS` | Ключ авторизации вашего доступа GigaChat |
| `GIGACHAT_SCOPE` | Scope, соответствующий ключу; в примере `GIGACHAT_API_PERS` |
| `GIGACHAT_MODEL` | Серверная модель, по умолчанию `GigaChat-3-Ultra` |
| `GIGACHAT_BASE_URL` | По умолчанию `https://api.giga.chat/v1` |
| `GIGACHAT_CA_BUNDLE_FILE` | Абсолютный путь к PEM-набору доверенных сертификатов при необходимости |
| `LATEX_COMPILER` | Необязательный путь к `xelatex`/`pdflatex`, иначе автоматический поиск |
| `LATEX_TIMEOUT_SECONDS` | Тайм-аут одной TeX-сборки, по умолчанию 60 секунд; допустимый диапазон 5–120 |

`run_local.py` загружает корневой `.env`. Уже заданные переменные процесса имеют приоритет. Конфигурация ключа и наличие SDK ещё не доказывают сетевую доступность ИИ: `/api/status` сообщает `ai_connection_verified: false`, а реальный запрос отдельно проверяет доступ.

В использованном доступе API были перечислены `GigaChat-2` (Lite), `GigaChat-2-Pro`, `GigaChat-2-Max`, `GigaChat-3-Lightning`, `GigaChat-3-Pro` и `GigaChat-3-Ultra`. Фотографии проверялись на Ultra. Название модели задаётся сервером; интерфейс не передаёт произвольную модель. Доступные модели и условия использования зависят от учётной записи провайдера.

## 3. TLS-сертификаты GigaChat

Приложение всегда проверяет TLS (`verify_ssl_certs=True`). Если стандартный набор доверия не распознаёт сертификат API, подготовьте отдельный набор для этого проекта по [официальной инструкции GigaChat](https://developers.sber.ru/docs/ru/gigachat/certificates). Ни системное хранилище, ни установленный `certifi` менять не требуется.

Проверенный вариант для Windows PowerShell:

~~~powershell
New-Item -ItemType Directory -Path '.local-certs' -Force | Out-Null
Invoke-WebRequest -Uri 'https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt' -OutFile '.local-certs/russian_trusted_root_ca_pem.crt'
.\.venv\Scripts\python.exe -c 'from pathlib import Path; import certifi; folder=Path(".local-certs"); target=folder/"gigachat-ca-bundle.pem"; target.write_bytes(Path(certifi.where()).read_bytes()+b"\n"+(folder/"russian_trusted_root_ca_pem.crt").read_bytes()); print(target.resolve())'
~~~

Укажите выведенный абсолютный путь в `GIGACHAT_CA_BUNDLE_FILE` локального `.env`. Этот набор объединяет обычные корневые сертификаты `certifi` и официальный Russian Trusted Root CA. Скачивание в команде тоже использует TLS-проверку. Если оно не проходит или требования провайдера изменились, сверьтесь с официальной инструкцией; не отключайте проверку сертификатов.

## 4. Локальный TeX

~~~powershell
xelatex --version
~~~

Если MiKTeX не добавлен в PATH, приложение также ищет его в стандартных каталогах Windows. Можно явно задать `LATEX_COMPILER`, например абсолютный путь к `xelatex.exe`. Приоритет — XeLaTeX, затем pdfLaTeX.

Шаблон использует `iftex`, `fontspec` (XeLaTeX), `inputenc`/`fontenc` T2A (pdfLaTeX), `babel` с русским языком, `amsmath`, `amssymb`, `multicol`, `geometry`, `tikz` и `xcolor`. Для XeLaTeX выбирается Arial, затем DejaVu Sans или Liberation Sans. Установите необходимые пакеты через официальный менеджер вашего TeX-дистрибутива до демонстрации. Автоматическая установка пакетов при сборке MiKTeX отключена.

Модуль больше не требует `mathtools`. На проверенном компьютере локальная сборка с установленными пакетами проходит без их дополнительной установки. Само наличие компилятора не гарантирует наличие всех зависимостей на другом компьютере.

Сетевого fallback нет. Если локальный TeX отсутствует или завершился с ошибкой, PDF не выдаётся как успешно созданный. Если не удалось собрать ответы, весь запрос сборки возвращает ошибку, а не неполный комплект.

## 5. Запуск

Windows:

~~~powershell
.\.venv\Scripts\python.exe run_local.py
~~~

Linux/macOS:

~~~bash
.venv/bin/python run_local.py
~~~

Откройте [http://127.0.0.1:3005](http://127.0.0.1:3005). Остановка — Ctrl+C. Другой порт задаётся как `run_local.py --port 3015`. Отдельный каталог исходников — `--repo-root /absolute/path/to/project`.

Сервер слушает только `127.0.0.1`; debugger и reloader выключены. Frontend использует `/api/`. Старый `/worksheet-api/` поддерживается адаптером как алиас. Прямой запуск `python app/backend/app.py` также работает на localhost без debug, но `run_local.py` остаётся рекомендуемой точкой входа.

## 6. Проверка без ИИ

1. Выберите «Математика» или «Физика».
2. Нажмите «Открыть пример». Он помечен как подготовленный вручную.
3. Проверьте условия, формулы и ответы в LaTeX. При необходимости измените тему, подпись учителя, макет или содержимое.
4. Отметьте «Я проверил(а) условия, формулы и ответы» и нажмите «Собрать PDF».
5. Откройте рабочий лист и ответы; проверьте обе страницы перед печатью.

Проверенные ответы ручного математического примера: корни 2 и 3; сумма дробей 19/12; сумма корней 13. Физического: путь 32 м; ток 3 А; плотность 2,7 г/см³. Это контрольные материалы демонстрации, а не результат ИИ.

## 7. Работа с фотографиями и вторым вариантом

Загрузите чёткие PNG/JPEG: не более 10 файлов и 20 МБ суммарно. Нажмите «Подготовить черновик с ИИ». Учитель проверяет распознанные числа, формулы, единицы и вычисления, затем собирает лист. Для похожего варианта выберите уровень сложности; второй черновик также откроется в редакторе и требует отдельной проверки.

PDF на входе явно отклоняется с объяснением. Пока сохраните нужные страницы как изображения. Вставка DOCX, генерация только по теме, Marp и MAX ещё не реализованы.

В настоящих тестах GigaChat-3-Ultra распознал контрольные изображения по математике и физике. В математическом черновике один ответ на дробное выражение оказался неверным. В физическом примере ответы 6 Н, 4 Дж и 2 А верны; после проверки и правки оформления получены одностраничные лист и ответы. Успешный запрос или PDF не означают корректность всех заданий. Учитель должен проверить также лишние добавленные моделью подписи, критерии и разрывы страниц.

## 8. Файлы, история и исходник

- История хранится в `app/backend/worksheets.db`; она общая для этого локального экземпляра.
- PDF, полный TEX и журналы локальной сборки находятся в `app/backend/static/generated/`.
- Исходные загрузки хранятся во временном локальном каталоге во время запроса и удаляются после него. Удаление у провайдера не гарантируется текущей версией SDK; правила хранения проверяйте у провайдера.
- API успешной сборки возвращает `pdf_url`, при наличии `keys_url`, а также `tex_url`. В текущем UI есть ссылки на PDF, ответы и полный TEX. Тело LaTeX можно копировать из редактора.

`TaskBox` и `WriteField` определены в шаблоне. Для самостоятельной TeX-сборки используйте полный TEX из результата, а не один фрагмент тела из редактора.

## 9. API и тесты

| Метод и путь | Назначение |
|---|---|
| `GET /api/status` | Возможности сервера без выдачи секретов |
| `GET /api/demo?subject=math` | Ручной пример; для физики `subject=physics` |
| `POST /api/process` | Multipart `files`, `subject`, `task_count`; возврат LaTeX-черновика |
| `POST /api/compile` | JSON `latex_code`, `topic`, `teacher_name`, `layout`, `is_variant2`; ссылки на файлы |
| `POST /api/generate_similar` | Form `original_text`, `subject`, `task_count`, `difficulty`; черновик второго варианта |
| `GET /api/history` | Локальная история; `limit` от 1 до 100 |
| `GET /api/generated/имя-файла` | PDF или TEX из каталога результатов |

`/api/debug-env` закрыт. Ошибки ИИ возвращаются как ошибки HTTP/JSON, а не строка «успешного» LaTeX. Ошибка TeX возвращает 422; отсутствие компилятора — 503; PDF или неверный тип файла на входе — 415.

Проверки backend запускаются из корня проекта:

~~~powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
~~~

Проверены 34 теста без обращения к провайдеру. Отдельно выполнены 29 проверок LaTeX, реальные сборки ручных примеров по двум предметам и сетевые тесты Ultra с изображениями по математике и физике. Это проверки конкретных сценариев; измерений надёжности на большом наборе школьных материалов пока нет.

## 10. Границы локального прототипа

TeX запускается с `no-shell-escape`, тайм-аутом, проверкой кода завершения и ограничением допустимых команд. Это меры для демонстрации, а не полноценная производственная песочница. Для публичного сервиса нужны изоляция компилятора, авторизация, раздельные файлы и история, очередь и лимиты запросов.

В репозитории также есть Telegram-бот, Dockerfile и серверные deployment-скрипты. Они не проверялись в этом локальном цикле и не являются готовым рецептом публикации обновлённого сервиса. Основной поддержанный запуск этой версии — `run_local.py`.

MAX/Сферум, централизованные квоты для школы и партнёрский доступ — следующие этапы. Партнёрство или бесплатная квота не подтверждены; модель оплаты ещё не определена.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| ИИ не подключён | Корневой `.env`, установленный SDK, scope и действующий доступ; перезапустите сервер после изменения настроек |
| Ошибка API или TLS | Доступность модели и корректность `GIGACHAT_CA_BUNDLE_FILE`; проверку TLS оставьте включённой |
| PDF недоступен | Путь к TeX, пакеты и шрифты; начните с ручного примера |
| Ошибка LaTeX | Условия и формулы в редакторе, разрешённые команды и журнал в `static/generated/` |
| Лист разошёлся на лишние страницы | Уменьшите поля `WriteField`, уберите лишние подписи или измените макет; заново просмотрите PDF |

Конкурсная версия «ЛистОК» — команда «Код урока».
