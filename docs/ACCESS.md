# Что подключить владельцу проекта

Секреты вводятся локально в `.env` в корне проекта. Не отправляйте их в чат, GitHub или скриншотах. Файл настроек уже подготовлен в рабочей копии; он исключён из Git и Docker-контекста.

## GigaChat

1. В кабинете GigaChat API создайте/выберите проект с доступом к API. Обычный вход в веб-чат GigaChat не заменяет API-доступ.
2. Запишите ключ авторизации в `GIGACHAT_CREDENTIALS`.
3. Укажите scope этого проекта в `GIGACHAT_SCOPE`. Для персонального доступа обычно используется `GIGACHAT_API_PERS`; окончательное значение берётся из кабинета.
4. В `GIGACHAT_MODEL` укажите модель, доступную этому проекту и поддерживающую изображения. Текущий исходный выбор проекта — `GigaChat-3-Ultra`; наличие проверяется отдельно. Пожелание использовать Max в Codex не меняет этот параметр.
5. При необходимости укажите PEM-файл доверенных сертификатов в `GIGACHAT_CA_BUNDLE_FILE`. TLS-проверка остаётся включённой.
6. Проверьте квоту и запустите `python scripts/check_connections.py --gigachat` из окружения проекта. Эта команда только проверяет список моделей. После этого проверяем реальные фото математики и физики и сверяем ответы.

Инструкции: https://developers.sber.ru/docs/ru/gigachat/guides/main ; https://developers.sber.ru/docs/ru/gigachat/guides/working-with-files ; https://developers.sber.ru/docs/ru/gigachat/certificates

## MAX

1. Получите конкурсный порядок выдачи/регистрации бота у организаторов. Общий порядок регистрации требует подходящего верифицированного профиля владельца; конкурс может выдавать специальный доступ.
2. Полученный токен запишите в `MAX_BOT_TOKEN`, имя бота — в `MAX_BOT_USERNAME`.
3. При необходимости укажите доверенный PEM-набор в `MAX_CA_BUNDLE_FILE`; TLS-проверка остаётся включённой. Выполните `python scripts/check_connections.py --max`. Выполняется только GET `/me`; сообщений бот не отправляет.
4. Разместим сервер по HTTPS, запишем адрес в `MAX_APP_URL` и укажем тот же URL в настройках мини-приложения. Адрес `127.0.0.1` для пользователей MAX не подходит.
5. Проверим на телефоне открытие приложения, подпись данных запуска, загрузку фото и получение файлов. При необходимости пройдём модерацию до финальной недели.

Реализовано: загрузка MAX Bridge, серверная HMAC-проверка подписи и возраста запуска до часа, серверные сессии, CSRF-защита, отдельные материалы и файлы каждого владельца, выход из профиля и нативное скачивание через временные ссылки. Всё это проверено локально с подписанными тестовыми запусками. Настоящий вход MAX пока не проверен — нужны HTTPS и привязка мини-приложения; токен уже проверен.

Инструкции: https://dev.max.ru/docs/chatbots/bots-coding/prepare ; https://dev.max.ru/docs/webapps/introduction ; https://dev.max.ru/docs/webapps/validation

## Docker / сервер

На текущем компьютере не установлены Docker и WSL. Образ собран и проверен в GitHub Actions; отдельный доступ к Docker Hub для этой проверки не понадобился. Готовый архив образа доступен в артефактах [успешной сборки](https://github.com/pavelneumoin/worksheet-creator/actions/runs/39723619649).

Для публичного продукта нужен сервер с Docker, HTTPS-домен и постоянное место для данных. Compose запускает веб-сервер, обработчик ИИ и обработчик TeX без сети; очередь и лимиты уже действуют. Предварительно закладываем 4 ГБ RAM, 2 vCPU и место под TeX-образ и материалы; окончательный размер — после нагрузки и политики хранения. Резервное копирование и восстановление уже реализованы. Перед открытым пилотом остаются нагрузочная проверка и проверка в MAX на настоящих телефонах.
