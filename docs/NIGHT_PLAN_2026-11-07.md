# Работа на ночь 7 ноября

Основание: запрос владельца проекта от 7 ноября. Публикация на сервере и GitHub
разрешена. Конкурсную заявку не отправляем. Привязку MAX выполняют организаторы.

## Приёмка

- [x] Учитель: фото/текст → фоновая обработка → результат сразу сверху:
  просмотр, PDF, ответы, комплект, бланк ответов, назначение классу.
- [x] Варианты рядом с результатом: аналогичный, легче, сложнее. Редактор и
  технические экспорты вторичны; длинные условия не отодвигают файлы.
- [x] Единая спокойная навигация на компьютере и телефоне. Кабинет учителя,
  школа для завуча, понятные пустые состояния и состояния обработки.
- [x] Отдельный красивый CMU-бланк кратких ответов на ученика, QR, версия,
  код, клетки; доступен до и после назначения. Полные решения тоже загружаются.
- [x] Аналитика школы, класса, темы и раздела; неподтверждённые/несданные
  результаты не становятся нулями. Учитель видит действия, завуч — охват и темы.
- [x] Промпты по этапам: буквальное распознавание, предложение уточнений к
  условию, независимая проверка ключа, варианты, краткие ответы, развёрнутые решения.
- [x] Для развёрнутой математики — тематические ориентиры с проверенными
  ссылками на ФИПИ, авторский пересказ принципов, обоснование по шагам,
  только рекомендация балла; окончательное подтверждение учителем.
- [x] Демо во всех разделах, отдельное от настоящих данных: классы около 30
  учеников, тригонометрия, логарифмы, текстовая физика, готовые проверки,
  расписание, школа и завуч. Синтетические результаты обозначены честно.
- [x] Кабинет ученика: персональное приглашение, MAX-вход, только свои работы,
  материал и задания, фото/PDF решений, статус, подтверждённые баллы и ошибки.
- [x] Возврат на исправление: комментарий учителя, новая попытка ученика,
  сохранение истории и прежнего подтверждённого результата до новой проверки,
  автоматическое появление исправления у учителя.
- [x] README: команда, быстрый сценарий, иллюстрации, демо, документация;
  технические детали и команды Docker ниже.
- [x] Проектная документация LaTeX + PDF: цель, задачи, аудитория, устройство,
  реализация, тестирование, результаты, ограничения, развитие, инструкция.
- [x] Положение конкурса: отдельная таблица соответствия после получения файла.
- [x] Регрессия, отрицательные проверки доступа, визуальная проверка PDF и
  мобильных экранов, резервная копия и восстановление, CI, сервер, GitHub-релиз.

## Порядок реализации

1. Инвентаризация и макет основного сценария.
2. Интерфейс результата и печатные формы.
3. Кабинет ученика и исправления с разграничением доступа.
4. Развёрнутая проверка и промпты; аналитика.
5. Сложные демо-материалы, проверка формул и PDF.
6. README, печатная документация, критерии.
7. Сквозные проверки, выпуск, резервная копия.

## Не менять молча

- Чужие работы недоступны ученику; QR и короткий код сами по себе не дают вход.
- В библиотеке материал личный до явной публикации.
- Уточнение условия не маскируется под исходный текст; сомнительный скан
  не превращается в придуманный ответ.
- Методические ориентиры не выдаются за официальную экзаменационную экспертизу.
- Демо не смешивается с настоящими оценками и статистикой.
