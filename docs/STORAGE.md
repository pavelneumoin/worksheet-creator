# Копии и обслуживание данных

Команды выполняются из корня проекта. Копия содержит частные материалы учителей; хранить её с тем же ограничением доступа, что и рабочую базу. `.env`, ключи, сертификаты, исходные фотографии и токены сессий в архив не входят. Автоматическое расписание ещё не установлено.

## Локально

```powershell
.\.venv\Scripts\python.exe scripts/manage_storage.py backup output/backups/listok-2026-10-22.zip
.\.venv\Scripts\python.exe scripts/manage_storage.py restore output/backups/listok-2026-10-22.zip output/restored-2026-10-22
.\.venv\Scripts\python.exe scripts/manage_storage.py cleanup
.\.venv\Scripts\python.exe scripts/manage_storage.py cleanup --apply
.\.venv\Scripts\python.exe scripts/manage_storage.py provider-cleanup
.\.venv\Scripts\python.exe scripts/manage_storage.py provider-cleanup --apply
```

Первый запуск cleanup — предварительный подсчёт. `--apply` выполняет очистку. По умолчанию срок — 30 дней, можно увеличить `--days`; меньше 7 дней запрещено. Личные материалы, опубликованные материалы и сохранённые версии не удаляются. Для повторного backup/restore выбирайте новое имя: существующий архив и существующий каталог не перезаписываются.

Копия использует SQLite backup API под блокировкой записи на время копирования файлов. Проверяется наличие всех файлов из базы; отсутствие хотя бы одного прерывает создание. ZIP содержит манифест SHA256 и размеры. Восстановление проверяет пути, состав, суммы, целостность SQLite и внешние ключи до появления конечного каталога. Восстанавливаются все владельцы, папки, версии и библиотека. Сессии/ссылки скачивания отзываются; активные задачи помечаются прерванными, запросы к платному ИИ не повторяются.

После проверки восстановленной копии остановите приложение и обработчики, задайте `LISTOK_DB_PATH=<новый каталог>/worksheets.db`, `LISTOK_GENERATED_DIR=<новый каталог>/generated`, `LISTOK_JOBS_DIR=<новый каталог>/jobs` и запустите приложение. Сначала проверьте локально, затем переключайте рабочее размещение. Старый каталог сохраняйте до приёмки восстановления.

## Docker Compose

Данные томов доступны служебной команде без сети:

```bash
docker compose run --rm --no-deps --entrypoint python compile-worker scripts/manage_storage.py backup /app/data/listok-backup.zip
docker compose cp listok:/app/data/listok-backup.zip ./listok-backup.zip
docker compose run --rm --no-deps --entrypoint python compile-worker scripts/manage_storage.py cleanup
docker compose run --rm --no-deps --entrypoint python ai-worker scripts/manage_storage.py provider-cleanup
```

Для каждого архива задавайте новое имя. Если образ запускается с read-only root, результаты проверок шаблонов (`/app/output`) требуют отдельного доступного на запись тома; штатные пользовательские PDF уже пишутся в `generated`.

Для аварийного восстановления: остановить три сервиса, проверить архив командой `restore` в новый каталог; подготовить **новые** тома данных/generated с владельцем UID 10001, перенести проверенную базу и каталог generated, подключить их в отдельной Compose-конфигурации. Старые тома не удалять до приёмки. Автоматического переключения или перезаписи production-томов скрипт не выполняет.

## Файлы GigaChat

Новые загрузки структурированного распознавания журналируются по ID. Обычный путь удаляет файл сразу в `finally`; неудачная очистка сохраняет запись. Команда `provider-cleanup --apply` повторяет удаление только **своих записанных** ID старше суток. Список всех файлов аккаунта не запрашивается. Ответ 404 считается уже выполненным удалением; временная ошибка оставляет запись для следующего запуска.

Ограничение: остаётся маленькое окно между успешной загрузкой у провайдера и записью ID в SQLite. Жёсткое завершение именно в этот момент может оставить неизвестный приложению файл. Старые загрузки до внедрения журнала также не обнаруживаются автоматически. Эти случаи требуют проверки владельцем у провайдера, а не массового удаления чужих файлов аккаунта.

Рекомендация для размещения: ежедневная копия вне рабочего диска, 7 ежедневных + 4 еженедельных; раз в неделю учебное восстановление в отдельное окружение. Расписание и внешнее хранилище подключаем после выбора сервера.
