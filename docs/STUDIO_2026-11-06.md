# Ноябрьская мастерская ЛистОК

## Создание и печать

Первый экран — создание листа. Фото/PDF/текст → личный черновик → проверка заданий
и ответов → оформление → лист ученика, отдельные ответы и комплект учителя.
Автоматического опубликования нет. Четыре шаблона, 1–2 столбца, 1–6 заданий на странице,
клетка/пустое поле/без поля, высота автоматически либо 1–10 см в интерфейсе.
После сборки можно сразу назначить лист в расписание.

## Проверка и статистика

«Проверка работ»: класс → назначенная версия → PDF из МФУ до 40 страниц и 15 МБ.
Страницы распознаются последовательно с промежуточным сохранением. Учитель сверяет
код и отмечает до пяти страниц одного ученика. Неизвестные коды и другая версия не
назначаются автоматически. Повторная пачка не создаёт дубликат. Сканы закрыты от других
профилей, удаляются из рабочего хранилища через семь дней; у резервных копий отдельный срок.

Проверяются **конечные ответы**, не вся логика развёрнутого решения. Совпадение с эталоном
предлагает один балл, остальные случаи требуют решения учителя. В статистику входят только
явно подтверждённые результаты. Пропуск и непроверенная работа не равны нулю.

Темы берутся из заголовка листа и редактируются для назначения. Фильтры: класс, тема,
период, для школы — учитель. Процент взвешен по сумме подтверждённых баллов и максимуму.
PDF: цветные таблицы, диаграммы, задания для повторения, результаты по кодам; доступен CSV.
Фактические наблюдения рассчитываются кодом. GigaChat получает агрегаты без имён учеников,
кодов, фото и ответов, предлагает методические действия. Старые рекомендации нельзя включить
в PDF после изменения статистики.

## Школа и ученики

Координатор создаёт пространство школы. Одноразовое приглашение действует семь дней.
Учитель явно разрешает просмотр статистики всех своих классов. Роль по приглашению —
только учитель. Завуч видит членов своей школы; сканы и ответы остаются у учителей.
Выход/отзыв участия закрывает новые запросы; ранее скачанные отчёты отозвать невозможно.

Коды учеников создаются по количеству или из вставленного списка имён, по одному на строку.
Имена остаются только в памяти страницы: сервер получает количество и версию класса.
Таблицу «имя → код» нужно скачать до перехода на другой экран. Имена не сохраняются
в браузерном хранилище или базе. Фото списка имён пока не распознаётся.

## Быстрый MAX

- `/quick`, «Быстрый лист» — инструкция; до 10 фото одним сообщением, один PDF или
  `/лист <текст>` — создание черновика в той же личной библиотеке.
- `/draft` — последний черновик с условиями и ответами прямо в чате.
- `/pdf`, «Проверил, собрать PDF» — подтверждение и сборка трёх PDF.
- `/files` — повторить готовые PDF; `/today`, «Сегодня» — листы из расписания по Москве.
- `/start` — одноразовая ссылка в кабинет для подробных правок.

Группы и каналы игнорируются. Медиа скачиваются только с CDN MAX без редиректов и токена
бота. Неоднозначная ошибка отправки не вызывает автоматический повтор. Команды позволяют
снова получить сохранённый результат. Бот и кабинет используют один MAX-профиль.

## Встроенный запуск — настройка владельца конкурсного бота

Бот `ideya_fiks_126_bot`, адрес `https://listok.84.201.135.165.sslip.io`.
Владелец должен привязать адрес в настройках мини-приложения **этого бота**, затем
проверить встроенный запуск и подписанный `initData`. Личный кабинет участника не даёт
прав на бота организаторов; токен Bot API не заменяет доступ владельца к этой настройке.
До привязки кнопка входа открывает веб-кабинет. Встроенный запуск не заявляется проверенным.

Источники: [мини-приложения MAX](https://dev.max.ru/docs/webapps/introduction/),
[кнопки](https://dev.max.ru/docs-api/use-cases/sending-messages/keyboard),
[загрузка файлов](https://dev.max.ru/docs-api/methods/POST/uploads).

хранятся в отдельной локальной базе и не переносятся в облако.
