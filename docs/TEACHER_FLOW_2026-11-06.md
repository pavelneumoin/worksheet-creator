# Сценарий учителя и следующий этап проверки

## План текущей проверки

1. Вход по персональной ссылке MAX — пользователь подтвердил открытие кабинета 6 ноября.
2. В отдельном учебном кабинете: создать лист, проверить ключ, собрать PDF и назначить классу.
3. Напечатать бланки ответов: один ученик на A4, код ученика, QR назначения и неизменяемая версия, до 30 номеров с клетками. Отдельно доступен пустой бланк.
4. Загрузить общий PDF с заполненными бланками, сверить распознавание, подтвердить баллы. После подтверждения вернуться к оставшимся страницам пачки.
5. Проверить школьный доступ на двух независимых профилях: только согласившийся учитель, только подтверждённые результаты; «не сдал» отдельно от нуля.
6. Проверить мобильный кабинет, сборку, резервную копию, сервер и GitHub Release.

## Почему отдельный бланк

Для коротких ответов ученик решает на обычном рабочем листе, а итог переносит в компактную таблицу. Учитель сканирует только бланки: число страниц равно числу учеников, независимо от объёма решений. Бланки класса уже содержат коды; ФИО в них нет. Пустой бланк предназначен для ручного заполнения кода.

27 клеток в строке, размер клетки 5,5 × 6 мм; до 30 заданий на A4. Печать односторонняя, масштаб 100%. Дробь — через `/`, несколько значений — через `;`. Если ответ длиннее, нужен полный скан решения. Этот режим оценивает конечные ответы, а не ход рассуждений.

## Приоритеты до 8 ноября

| Шаг | Что меняется для учителя | Как принять результат |
|---|---|---|
| Реальный пилот | 10–15 рукописных бланков с телефона и МФУ | Сравнить с ручной разметкой, записать время проверки и все ошибки OCR; отдельно дроби, минусы, единицы, пустые поля, зачёркивания |
| Только сомнительные | Фильтр «Нужно внимание», исходный фрагмент рядом с ответом | Каждый неуверенный ответ виден; ни один не превращается в ноль без учителя |
| Контроль пачки | Перед запуском видно число страниц, после — получено/осталось/дубликаты | Повтор PDF или страницы не удваивает результат; чужая версия требует явного исправления |
| Мобильная проверка | Один ответ на экране, крупный скан, закреплённые действия | Проверка одной рукой на 360–430 px, без горизонтальной прокрутки и потери черновика |
| Заморозка и демонстрация | Короткий воспроизводимый маршрут на учебном классе | Свежий Docker-образ, проверенный backup/restore, README и демонстрационный PDF; работа не подаётся автоматически |

## Следующий этап после демонстрации

1. **Метки бланка.** QR с назначением, версией и кодом ученика уже реализован. Следующий шаг — геометрические ориентиры для вырезания строки и многостраничные решения. Метка сейчас не подписана и не доказывает личность ученика; она помогает сопоставлению, итог подтверждает учитель. При плохом QR остаётся ручное сопоставление.
2. **Стабильная проверка.** Хранить координаты строк и показывать увеличенный фрагмент; разнести «не распознано», «ответ пустой», «ответ неверный». Сравнивать числовую эквивалентность и единицы детерминированно, а неточные случаи отдавать учителю.
3. **Критерии.** Настраиваемый максимум за задание, частичный балл и рубрика для развёрнутого решения. Новые критерии создают новую версию; старые результаты не пересчитываются незаметно.
4. **Повторение ошибок.** Из подтверждённых результатов — группы затруднений, варианты повторения и короткий отчёт для ученика. Сначала предпросмотр учителю; личная отправка в MAX — отдельное действие.
5. **Качество и затраты.** Версионированный набор обезличенных сканов: точность кода/номера/ответа, доля ручных исправлений, время на класс, стоимость страницы. Автоподтверждение запрещено до проверки на реальных рукописных данных.

Школьная статистика уже существует. Следующий шаг для завуча — полнота данных и динамика по темам; сравнение классов разной сложности нельзя представлять как рейтинг качества преподавания. ИИ предлагает методические действия, числовые показатели рассчитываются кодом.

## Границы

Проверка 6 ноября: пользователь подтвердил вход через MAX. В двух отдельных локальных профилях пройдено создание → PDF → назначение трём кодам → распознавание двух заполненных бланков через настоящий GigaChat → подтверждение 3/3 и 1/3 → подключение школы → отчёт завуча 2/3, 66,7%, один «не сдал». Школьный PDF из двух страниц проверен визуально. Первоначально GigaChat пропускал печатные коды; добавлен локальный QR-декодер. Повторный прогон прочитал оба кода и версии точно, сохранив все шесть ответов, в том числе неверный и пустой. Это синтетические сканы с имитацией письма, а не пилот с реальными детьми.

Макеты бланков проверены на 3 и 30 заданиях, полный комплект — 30 учеников × 30 заданий, ровно 30 страниц. QR проверен после сжатия и поворота; чужое назначение и несколько меток не дают автоматического сопоставления. В Edge проверены мобильные ширины 360, 390 и 430 px, сохранение папки, меню, нижняя навигация; горизонтальной прокрутки страницы нет.

Локальный декодер использует [zxing-cpp](https://github.com/zxing-cpp/zxing-cpp/blob/master/wrappers/python/README.md), генератор — [qrcode 8.2](https://pypi.org/project/qrcode/8.2/). Внешних запросов для чтения метки нет.

Вход через MAX работает по персональной ссылке. Открытие внутри нативного мини-приложения требует привязки HTTPS-адреса владельцем конкурсного бота. Фото списка учеников временно передаётся в GigaChat с подтверждением учителя; в постоянном списке остаются коды, таблица имён скачивается на устройство. Синтетические проверки не заменяют пилот с рукописными листами.
