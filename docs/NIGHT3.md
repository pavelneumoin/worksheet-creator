# Очередь, Marp и Docker — 22 октября 2026

## Что теперь работает

- Фото/текст, варианты и печать принимаются быстро, а работа выполняется отдельно от веб-сервера. Статусы «в очереди», «в работе», «готово», понятная ошибка; отмена доступна до начала обработки.
- SQLite хранит очередь. Перезагрузка страницы не останавливает обработку. Черновик сохраняется перед сборкой; результат ИИ автоматически становится личным материалом.
- Если учитель изменил лист во время сборки, готовый комплект остаётся отдельной версией. Новые правки не затираются.
- Повторная передача одного запроса с `Idempotency-Key` возвращает ту же задачу. При потере ответа интерфейс повторяет отправку с тем же ключом и снимком содержания.
- Готовый комплект: PDF листа, PDF ответов, LaTeX и ZIP с `worksheet.md`, `answers.md`, `listok.css`, `README.txt`. Источники используют одну схему заданий. Marp сохраняет столбцы, задания на странице, клетку/пустое поле/список и авторство основы.
- На мобильных экранах вместо встроенного PDF-плеера доступен раскрываемый просмотр условий с формулами; сам PDF открывается отдельной кнопкой. Ответы не попадают в этот просмотр.

## Ограничения очереди

Одна активная задача на профиль, максимум 30 ожидающих/выполняющихся задач в приложении. На весь экземпляр базы одновременно работают один обработчик ИИ и один обработчик сборки. Состояние очереди не зависит от числа открытых вкладок.

Распознавание ограничено 25 минутами на пакет до 10 фотографий, вариант — 5 минутами, сборка — 3 минутами; один запуск TeX — 60 секундами. У процесса есть heartbeat. После аварийной остановки задача получает ошибку, а не автоматически повторный платный запрос. Не начатая задача хранится до 24 часов, журнал результатов — 7 дней. Сами личные материалы не удаляются вместе с журналом.

Исходные фотографии в локальной очереди удаляются после завершения, ошибки или отмены. Нормальное завершение запроса GigaChat включает удаление загруженных файлов у провайдера; при принудительном уничтожении процесса это удаление может не успеть. Политика периодической очистки оставшихся файлов провайдера — отдельная задача перед открытым пилотом.

## Контейнерная поставка

Один образ `listok:night3`, три сервиса Compose. Постоянные тома `materials` (SQLite и очередь) и `generated` (готовые файлы). Все процессы работают от пользователя 10001, без Linux capabilities, с запретом повышения привилегий и файловой системой образа только для чтения. Временные файлы находятся в ограниченном tmpfs. Обработчик компиляции не имеет сети и не получает `.env` или ключи GigaChat/MAX.

[Первая успешная сборка](https://github.com/pavelneumoin/worksheet-creator/actions/runs/39723619649) проверила образ, тесты, настоящие PDF, отдельный процесс очереди, экспорт Marp, три работающих сервиса и перезапуск веб-сервера. В артефакте `listok-docker-image` лежат сжатый Docker-образ и SHA256. Сборки помечены своим коммитом; берите Compose из того же коммита. Последующие сборки хранят артефакт 90 дней.

## Проверки

- 91 unittest: включая 11 проверок очереди и 3 проверки Marp; владельцы, CSRF, дедупликация, конкурентный захват, авария обработчика, отмена, сохранение версии, приватный ZIP и истечение ссылки.
- `scripts/smoke_queue.py`: настоящая сборка в дочернем процессе без сети/ключей, повторная инициализация базы между постановкой и исполнением, PDF/ответы/Marp, сохранение и удаление временных файлов.
- `scripts/smoke_deployment.py`: подписанный тестовый запуск MAX, постановка через API, работа другого контейнера, скачивание всех четырёх файлов и материал после перезапуска.
- Реальный движок Marp: восемь документов (задания/ответы для четырёх макетов), A4, число страниц, формулы, экранирование пользовательского HTML и ссылок. Для проверок используется Marp Core 4.4.0 с закреплёнными исправленными зависимостями; `npm audit` — 0 уязвимостей. Node не нужен серверу приложения.
- Экспортированный Markdown проверен преобразованием в PDF через Marp CLI 4.5.1. Визуально просмотрены математика, физика, два столбца и ответы. Размер PDF — A4, для 3 заданий по 2 на страницу получены 2 страницы.
- Мобильный браузер: отправка, перезагрузка во время сборки, восстановление статуса, открытие результата и скачивание реального ZIP. Ширины 320/375/390/430 px проверяются без горизонтального переполнения; проверка внутри настоящего MAX ещё впереди.
- Живой запрос GigaChat через отдельный обработчик: два введённых задания сохранены автоматически, ответы `19/12` и `x = 4` сверены вручную. В браузере нет ошибок консоли; кнопки готового листа на узких экранах имеют высоту не менее 44 px.

Официальные источники формата: [Marp CLI](https://github.com/marp-team/marp-cli), [темы Marpit](https://marpit.marp.app/theme-css), [формулы Marp](https://github.com/marp-team/marp-core/blob/main/docs/markdown.md).
