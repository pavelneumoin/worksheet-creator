# Разбор развёрнутого решения

Это дополнительная помощь учителю. Основной сценарий ЛистОК — создание и печать
рабочих листов; краткие ответы можно собирать на отдельном бланке A4.

## Два этапа

1. Модель распознавания видит скан и номера заданий. Она переписывает видимые шаги,
   не получает ключ ответов и не исправляет за ученика нечёткий текст.
2. Модель анализа получает расшифровку, условие, ключ и тематический ориентир.
   Она проверяет ключ независимо, объясняет ошибку, цитирует шаг из расшифровки
   и предлагает балл по шкале рабочего листа 0–1 с шагом 0,25.

Если фрагмент не прочитан либо основание рекомендации отсутствует в расшифровке,
программа убирает предложенный балл. Учитель видит скан, расшифровку, основание,
следующий шаг и источники. Рекомендация не переносится в оценку автоматически.
После изменения работы прежний анализ помечается как устаревший.

## Методические ориентиры

Короткие авторские памятки для алгебры, логарифмов, тригонометрии, геометрии,
текстовых задач и физики находятся в `app/backend/utils/methodology.py`.
Для развёрнутой математики учтены общие принципы материалов ФИПИ: рассматривать
обоснование и полноту решения, допускать корректные альтернативные способы,
различать вычислительную ошибку и неверный метод. Для логарифмов проверяется ОДЗ,
для тригонометрии — семейства корней и отбор на промежутке.

Источники: [ОГЭ, математика, 2026](https://doc.fipi.ru/oge/dlya-predmetnyh-komissiy-subektov-rf/2026/mr_oge_matematika_2026.pdf),
[ЕГЭ, математика, 2026](https://doc.fipi.ru/ege/dlya-predmetnyh-komissiy-subektov-rf/2026/matematika_mr_ege_2026.pdf).
Это пересказ общих подходов, не официальная экзаменационная шкала и не замена эксперта.
Критерии конкретного задания экзамена нельзя автоматически переносить на любой лист.

## Проверки и ограничения

В автоматических тестах проверяются отсутствие ключа в запросе распознавания,
привязка основания к тексту и запрет выставления балла при недостаточных данных.
Отдельный запрос к действующему API на синтетическом печатном примере распознал
тригонометрическое решение и обнаружил посторонний корень в логарифмическом.
Этого недостаточно для заявления точности на рукописных работах.

Следующий этап — размеченный набор реальных обезличенных сканов, двойная проверка
учителями, измерение ошибок по темам и отдельно по качеству почерка. Исправления
учителя не следует автоматически использовать как обучающие данные без согласия.

Опциональная проверка реального API (расходует токены):

```bash
python scripts/smoke_solution_analysis.py --live
```

Параметры запуска и требуемое подтверждение смотрите в `--help`.
