# Печать, кабинет и дальнейшая проверка работ

Срез реализации: 22 октября 2026.

## Четыре структуры LaTeX

| Шаблон | Как устроен | Где полезен |
| --- | --- | --- |
| Компактный (`list`) | Нумерация, условие, выбранное поле; без внешних рамок | Короткие упражнения, домашнее задание |
| Карточки (`cards`) | Условие и поле решения объединены рамкой | Самостоятельная практика, наглядное отделение заданий |
| По шагам (`guided`) | Условие; слева «Дано» и «Найти», справа решение и ответ | Расчётные задачи по физике, обучение записи решения |
| С проверкой (`check`) | Решение и ответ; справа баллы и комментарий учителя | Самостоятельная/контрольная работа; в узкой колонке проверка переносится вниз |

Любой шаблон совместим с 1–2 столбцами, настройкой количества заданий и клеткой/пустым полем/решением в тетради. В двух последних структурах остаются смысловые подписи и строки даже при отключённой клетке. Для них начинайте с 2–3 заданий на странице; длинные условия требуют меньшей плотности. Переполнение не выдаётся за корректный PDF — интерфейс предлагает снизить плотность. Фиксированного обещания «любые шесть задач поместятся» нет.

Настройки доступны на шаге «Оформление» и сохраняются вместе с материалом в профиле. Будущий пункт бота «Оформление» должен открывать этот же экран; схема `settings.template`, `columns`, `tasks_per_page`, `field`, `variant`, `lesson_date`, `print_sides` общая. Отдельного переключателя в живом MAX-боте пока нет: ожидаем токен.

Основной текст — **CMU Serif**, код версии — **CMU Typewriter Text**, формулы — Computer Modern. Шрифты и оригинальная лицензия входят в образ и репозиторий. XeLaTeX собирает документ в два прохода без сети. Структуры применяются к PDF/TEX; экспорт Marp пока сохраняет свой прежний макет A4, не имитирует четыре TeX-структуры.

## Колонтитулы и печать

- Сверху на каждой странице: сокращённая тема слева, класс и вариант справа; поля ограничены по ширине, длинная подпись переносится.
- Первая страница: тема, необязательный учитель, имя ученика от руки, класс, дата. На продолжении снова есть строка имени.
- Снизу: 12-значный код содержания, «ЛистОК», страница / всего страниц. Код совпадает у листа и отдельного ключа ответов; при изменении содержания или ответов меняется.
- Для обычной печати поля по 17 мм. Для двусторонней — зеркальные 20 мм у корешка и 14 мм снаружи; переворот по длинной стороне выбирается в диалоге принтера. Пустые страницы автоматически не добавляются. При нескольких индивидуальных комплектах печатать каждый отдельно, чтобы следующий ученик не начинался на обороте предыдущего.
- Чёрно-белая вёрстка без цветовых заливок; клетки 5 мм. Нижние подписи вынесены за рабочие поля.
- Ключ имеет явную подпись «КЛЮЧ ДЛЯ УЧИТЕЛЯ», собственную нумерацию страниц и тот же код содержания.

Код — идентификатор содержания, **не пароль, не идентификатор ученика и не разрешение на просмотр ответов**. Одинаковое содержание имеет одинаковый код; будущая проверка ищет его только внутри кабинета владельца. Для назначения классу понадобится отдельная сущность работы и приглашения учеников.

## Что хранит кабинет уже сейчас

Личный черновик → папка (например, «8А · Физика») → архив или «В работе». Папки и архив хранятся на сервере, видны после повторного входа. Поиск сочетается с фильтрами. Архив обратим и сохраняет файлы.

Каждая новая сборка через очередь создаёт неизменяемую **версию для печати**: исходный JSON со всеми заданиями и ответами, код, ревизия, дата, PDF, отдельный ключ, TEX, Marp. Старые версии доступны через «Папка и версии». Можно скачать старый лист/ключ или создать отдельную копию для редактирования. Изменение черновика не меняет ранее выданные PDF. История версий начинается с этой сборки приложения: старые PDF автоматически не реконструируются.

Все операции проверяют владельца на сервере. Удаление материала удаляет связанные с ним версии и файлы; архивирование сохраняет их. Срока автоматического удаления сохранённых материалов и версий нет. Очистка удаляет только старые непривязанные файлы, не сохранённые версии.

## Проверка

`python scripts/check_templates.py` собирает восемь случаев (4 структуры × 2 ширины), по две страницы заданий и отдельный ключ. Проверяет число страниц, встроенный CMU, код и разрешённые номера страниц. Каталог: `output/pdf/listok-template-catalogue.pdf`.

`python -m unittest discover -s tests` проверяет изоляцию кабинетов, сохранение версий при правках, запрет присоединения чужого по содержанию PDF, удаление всех версий, совместимость старых настроек и резервное восстановление. Визуально проверяем первую и последующие страницы, ответы, двухколоночные макеты и мобильные формы. Реальный MAX и бумажная печать на школьном принтере остаются отдельными приёмочными проверками.
