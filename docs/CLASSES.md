# Классы и назначение рабочих листов

Реализовано 22 октября 2026. Раздел «Классы» доступен в кабинете учителя. Данные хранятся в SQLite и входят в общую резервную копию вместе с версиями листов и файлами.

## Как пользоваться

1. Открыть «Классы», ввести название, например «8А · 2026/27».
2. Вставить список: один ученик на строку. Имена можно исправлять, учеников — архивировать и возвращать. Для полных тёзок добавить отчество или инициал, чтобы отличать записи.
3. Нажать «Назначить лист». Выбрать сохранённый материал и конкретную готовую версию PDF. Название, срок сдачи и комментарий видны перед назначением. Срок и комментарий необязательны.
4. Открыть работу на вкладке «Работы»: там зафиксированы задания, отдельные ответы для учителя, код версии и состав учеников. Из «Моих материалов» тоже можно назначить лист: кнопка у карточки и у каждой версии.

Для назначения нужно сначала сохранить и собрать PDF. Пустой или архивный класс не принимает новые работы. Список добавляется целиком: при ошибке или повторяющемся имени частично добавленных записей не остаётся. Поиск по имени помогает в длинном списке.

## Что фиксируется

- Ссылка на неизменяемую версию: условия, ключ ответов, PDF, код содержания. Последующая правка черновика её не меняет.
- Идентификаторы и имена текущих неархивных учеников, название класса на момент назначения. Новые ученики не добавляются в старую работу автоматически; изменение имени или архивирование не переписывает её состав.
- Название работы, комментарий и дата сдачи. Дата — календарный день без автоматической блокировки приёма; приёма ответов в этом этапе ещё нет.

Назначение можно закрыть и открыть снова, если класс не в архиве. «Закрыта» — состояние для учительского учёта, оно не означает проверку или выставленную оценку. Для другого состава, версии или срока создаётся новое назначение, прежнее закрывается.

Назначенный материал нельзя удалить: сервер предлагает архив. Ограничение действует и для закрытых назначений. Это сохраняет эталон и файлы для дальнейшей проверки работ.

## Надёжность и границы

Все маршруты требуют серверную сессию. Изменения требуют CSRF и допустимый Origin; владелец берётся только из сессии. Другой учитель не видит классы, имена, назначения и файлы по известному ID. Никаких публичных ссылок на списки учеников нет.

Изменение класса или списка требует актуальную `revision`. Назначение проверяет ту же ревизию в одной SQLite-транзакции. При конфликте интерфейс предлагает обновить класс. Повтор запроса с прежним `request_key` возвращает то же назначение даже после изменения состава; другой запрос с тем же ключом отклоняется. На телефоне после сетевого сбоя доступна кнопка повтора с тем же запросом. Если вкладка была полностью закрыта до подтверждения, сначала проверьте вкладку «Работы» перед новым назначением.

Лимиты: 100 классов на кабинет, 200 учеников на класс вместе с архивом, до 100 имён за одно добавление, 500 работ на класс. Архив не удаляет данные.

Сейчас назначение сохраняется **в кабинете учителя**. Привязки учеников к профилям MAX, рассылки, приёма фото, оценок и отчётов пока нет. Списки учеников не отправляются в GigaChat. Следующий этап — приглашение с проверенной привязкой профиля и подтверждением учителя; затем приём и проверка работ. См. [план проверки](GRADING_ROADMAP.md).

## API и проверки

| Маршрут | Назначение |
| --- | --- |
| `GET/POST /api/v2/classes` | Список / новый класс |
| `GET/PUT /api/v2/classes/:id` | Карточка / название и архив с `revision` |
| `POST /api/v2/classes/:id/students` | Массив `names` и `revision` |
| `PUT /api/v2/classes/:id/students/:student_id` | Имя, архив и `revision` класса |
| `POST /api/v2/classes/:id/assignments` | `edition_id`, `title`, `due_date`, `instructions`, `revision`, `request_key` |
| `GET/PUT /api/v2/assignments/:id` | Зафиксированная работа / `status` и ревизия назначения |

14 интеграционных тестов используют настоящую SQLite: изоляция владельцев, CSRF, конкурирующие повторы, состав и версия после правок, атомарный список, архив, защита файлов, миграция, резервная копия и восстановление. Docker smoke дополнительно проходит весь путь с настоящим PDF и повторно открывает назначение после перезапуска веб-контейнера.

## MAX

Токен получен и сохранён только в локальном игнорируемом `.env`. Проверка [GET /me](https://dev.max.ru/docs-api/methods/GET/me) с TLS подтвердила имя `ideya_fiks_126_bot`; ссылка: [бот команды](https://max.ru/ideya_fiks_126_bot). Сообщения при проверке не отправлялись.

Для настоящего входа остаются HTTPS-сервер, `MAX_APP_URL` и привязка этого адреса в настройках мини-приложения. [Официальные шаги подключения](https://dev.max.ru/docs/webapps/introduction). Внешний хостинг пока не настроен; проверка токена не означает готовность запуска мини-приложения в MAX.
