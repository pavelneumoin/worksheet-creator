# Классы, коды учеников и расписание

Обновлено 23 октября 2026 по голосовым требованиям. Данные принадлежат учителю, хранятся в SQLite и входят в резервную копию.

## Сценарий учителя

1. Создать класс, например «8А · 2026/27».
2. Указать **количество** учеников. Каждый получает постоянный код вида `У-82DFA942ED`. Сервис не принимает ФИО в списке учеников.
3. Скачать CSV с кодами и пустой колонкой ФИО. Заполнить её **на своём устройстве** и сохранить. Повторное скачивание выдаёт те же коды с пустыми ФИО: сервис не может восстановить личную таблицу учителя.
4. «Назначить лист»: выбрать материал и готовую версию PDF, указать название, при необходимости дату проведения, срок сдачи и комментарий. Срок сдачи не может быть раньше проведения.
5. В «Расписании» выбрать месяц и открыть работу. Работа без даты проведения остаётся в классе, в календарь не попадает.

Код не меняется при архивировании и восстановлении. Новому ученику создаётся новый код; код выбывшего не переиспользуется. Поиск — по коду. Максимум 100 классов, 200 учеников вместе с архивом на класс, 100 за одно добавление, 500 работ на класс. Короткий код используется в контексте класса; внутренний идентификатор — UUID. Код сам по себе не подтверждает личность.

## Что фиксируется

- Неизменяемая версия листа: условия, ключ, PDF и код содержания. Правки черновика её не меняют.
- Идентификаторы и коды текущих неархивных учеников, название класса. Позднее добавленные ученики не включаются в старую работу автоматически.
- Название, дата проведения, срок сдачи и комментарий. Для другой версии, состава или даты создаётся новое назначение; старое закрывается.

«Закрыта» — состояние учительского учёта, а не проверенные ответы или оценки. Назначенный материал нельзя удалить даже после закрытия; доступен архив. Приёма ответов, оценивания, отчётов и личной рассылки пока нет: [следующие этапы](VOICE_REQUIREMENTS_2026-10-23.md).

## Переход старой базы на коды

В старых базах `students.name` и `assignment_students.name` могли содержать имена. Название столбцов оставлено для совместимости; после перехода в них только коды. Новые API-записи всегда кодовые; API никогда не возвращает старые ФИО.

На **остановленном приложении**, перед переносом старой базы на сервер:

```bash
python scripts/migrate_student_codes.py --export output/private/student-mapping.csv
```

Сначала создаётся новая частная CSV-таблица соответствия, затем одной транзакцией заменяются имена в списках и снимках назначений. ID и состав сохранены. Существующий файл не перезаписывается. При ошибке записи таблицы база не меняется. Повторный запуск после успешного перехода ничего не меняет. Завершают переход secure_delete, checkpoint и VACUUM текущей базы. Старые резервные копии **могут содержать имена**; они автоматически не переписываются.

Таблицу оставить у учителя. Не переносить её в Git, Docker-образ или общий каталог сервера. Для новой пустой базы команда не нужна. После восстановления старой резервной копии выполнить переход до запуска. В локальной демонстрационной базе 3 записи и 3 снимка переведены 23 октября; таблица в игнорируемом `output/private/`.

## Надёжность

Все маршруты требуют сессию; изменения — CSRF и допустимый Origin. Чужие классы, ученики, календарь, назначения и PDF недоступны даже по известному ID. Изменения защищены `revision` и SQLite-транзакциями. Повтор назначения с тем же `request_key` возвращает прежнюю работу; другое содержание с тем же ключом отклоняется.

После сетевого сбоя повтор используется с тем же ключом. Если вкладку закрыли до ответа, сначала проверить «Работы». Добавление учеников защищено ревизией: повтор прежней операции не создаёт второй список.

## API

| Маршрут | Данные |
| --- | --- |
| `GET/POST /api/v2/classes` | Список / `name` класса |
| `GET/PUT /api/v2/classes/:id` | Карточка / `name`, `archived`, `revision` |
| `POST /api/v2/classes/:id/students` | Только `count`, `revision`; имена отклоняются |
| `PUT /api/v2/classes/:id/students/:student_id` | Только `archived`, `revision`; код неизменяем |
| `POST /api/v2/classes/:id/assignments` | `edition_id`, `title`, `scheduled_date`, `due_date`, `instructions`, `revision`, `request_key` |
| `GET/PUT /api/v2/assignments/:id` | Работа / `status`, `revision` |
| `GET /api/v2/schedule?month=2026-10` | Личные работы по проведению, включая закрытые |

Привязки MAX user_id пока нет. Она потребует отдельного приглашения и подтверждения учителем. Реальный запуск и скачивание CSV внутри MAX нужно проверить после HTTPS-размещения: локальная эмуляция не заменяет физический телефон.
