# ЛистОК

![ЛистОК: рабочие листы по математике и физике](./banner.png)

**Фото заданий → редактируемый LaTeX → рабочий лист A4 и ответы в PDF.**

«ЛистОК» помогает учителям математики и физики готовить материалы по собственным заданиям. Дроби, корни, индексы, производные и физические единицы требуют аккуратного ручного набора в Word. Сервис готовит черновик с формулами, а LaTeX оформляет его для печати. Учитель проверяет условия, вычисления и ответы и может изменить исходный текст.

Конкурсная версия [«ЛистОК»](https://github.com/pavelneumoin/worksheet-creator) для хакатона «Идея фикс» 2026. Команда «Код урока», ГБОУ «Школа 2200», Москва. Направление — **«Арсенал мастера»**. Стадия — **локальный прототип**.

## Попробовать

1. Запустите проект по [инструкции RUN.md](./RUN.md).
2. Откройте [локальный сайт](http://127.0.0.1:3005).
3. Выберите математику или физику и нажмите «Открыть пример».
4. Проверьте или измените LaTeX, отметьте проверку содержания и соберите PDF.

Ручные примеры работают без ключа ИИ: в каждом по три проверенных задания и ответы. Они явно отмечены как подготовленные вручную. Для распознавания своих фотографий и создания второго варианта нужен серверный доступ к GigaChat.

## Что работает

| Возможность | Текущая реализация |
|---|---|
| Математика и физика | Выбор предмета, отдельные примеры и инструкции модели |
| Загрузка заданий | PNG/JPEG, до 10 файлов и 20 МБ на запрос |
| Подготовка черновика | GigaChat API; модель задаётся на сервере |
| Проверка и исправления | Редактируемый LaTeX для первого и второго вариантов |
| Печать | A4, одна или две колонки, поля для письменного решения |
| Ответы | Отдельный PDF, если раздел ответов есть в черновике |
| Повторная работа | Локальная история в SQLite |
| Другой вариант | Черновик той же, меньшей или большей сложности через ИИ |

Количество задач на странице задаёт ориентир для генерации. Фактическое размещение зависит от длины условий и полей для решения; готовый PDF нужно просмотреть.

PDF на входе пока не поддерживается: сохраните нужные страницы как PNG/JPEG. Интеграция с MAX и Сферумом, отдельный поток PDF/сканов, многопользовательский доступ и дополнительные шаблоны Marp входят в план развития.

## Как устроен сервис

Браузерный интерфейс на HTML/CSS/JavaScript обращается к Flask API. Сервер отправляет фотографии в GigaChat и возвращает тело LaTeX в редактор. После проверки учителем локальный TeX-компилятор собирает лист и отдельные ответы. SQLite хранит историю этого экземпляра приложения.

Шаблон использует LaTeX, TikZ и математические пакеты. Автоматический выбор предпочитает **XeLaTeX**, затем **pdfLaTeX**. Сетевой компилятор отключён: при отсутствии локального TeX сервер сообщает об ошибке и не отправляет документ во внешний сервис.

Модель по умолчанию — `GigaChat-3-Ultra`; её можно задать через `GIGACHAT_MODEL`. В проверенном доступе API перечислены `GigaChat-2` (Lite), `GigaChat-2-Pro`, `GigaChat-2-Max`, `GigaChat-3-Lightning`, `GigaChat-3-Pro` и `GigaChat-3-Ultra`. Это список конкретного доступа на момент проверки, а не обещание доступности всех моделей каждому пользователю. Для фотографий в этой работе проверялся Ultra.

В репозитории также есть отдельный Telegram-бот и альтернативный модуль Yandex. Они не являются интеграцией MAX и не входят в проверенный основной сценарий этой версии.

## Что проверено и что ещё нужно проверить

- Локально собраны PDF по математике и физике: по три вручную заданных задания и отдельные ответы; проверены формулы, единицы, кириллица и A4.
- Пройдены 29 проверок модуля LaTeX и 34 проверки backend без обращения к ИИ, включая ошибки ввода, ограничения загрузки, обработку ошибок компиляции и отсутствие внешнего PDF-fallback.
- Выполнены настоящие запросы с изображениями по математике и физике к GigaChat-3-Ultra при включённой TLS-проверке. В математическом черновике один ответ на действие с дробями оказался неверным. В физическом примере все три ответа верны (6 Н, 4 Дж, 2 А); после проверки и правки оформления получены одностраничные лист и ответы. Это подтверждает работу конкретного сценария, а не качество на большой выборке.

Экономия времени, точность распознавания и педагогический эффект пока не измерены. План пилота: 5 учителей, 20 листов, до 100 учеников. Это план, а не фактический охват. Сравним ручную подготовку в Word и работу через сервис на одинаковых заданиях, включая время проверки и исправления.

Локальная TeX-сборка ограничивает команды, время выполнения и размер текста; shell escape запрещён. Эти меры предназначены для локальной демонстрации и не заменяют изоляцию компилятора для публичного сервиса. История пока общая для экземпляра: авторизация и разделение данных пользователей ещё предстоят.

## Адаптация для MAX и доступ к ИИ

План — мини-приложение MAX для пользователей Сферума: HTTPS-сайт, бот, MAX Bridge и серверная проверка данных запуска. Команде предстоит подтвердить порядок доступа, реализовать выдачу материалов и провести пилот. [Документация MAX](https://dev.max.ru/docs/webapps/introduction).

Целевой сценарий не требует личного API-ключа учителя: ключ, квоты и расходы обслуживает сервер проекта. В локальном прототипе сервер уже обращается к провайдеру по своей конфигурации. Партнёрство, бесплатные квоты и источник финансирования не подтверждены.

Основной провайдер — [GigaChat API](https://developers.sber.ru/docs/ru/gigachat/guides/working-with-files). В качестве альтернативы для сканов рассматриваются [Yandex Vision OCR](https://aistudio.yandex.ru/ru/docs/vision/concepts/ocr/models) и [YandexGPT в Yandex AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/models). Эти альтернативы ещё не подключены к текущему сценарию.
