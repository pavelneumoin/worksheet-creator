# ЛистОК

**Фотографии заданий → редактируемые карточки → рабочий лист A4 и отдельные ответы.**

Проект команды **«ЛатехТим»** для хакатона Сферума «Идея фикс» 2026, направление «Арсенал мастера». Капитан по актуальной регистрации — **Николай Семченков**. Участники: Максим Скоков, Дмитрий Мазка, Таисия Алексинская, Анастасия Почкина.

## Текущая стадия: очередь, Marp и проверенный Docker, 22 октября

Готов локальный сквозной сценарий с новым адаптивным интерфейсом в светло-серой гамме и фиолетовых акцентах, основанных на официальном сайте Сферума. [Источники цветов и решения дизайна](docs/DESIGN.md).

- Фотографии PNG/JPEG (до 10, до 20 МБ суммарно, до 15 МБ одна) или текст заданий.
- GigaChat возвращает структурированные задания и ответы. Каждая страница распознаётся отдельным запросом, затем задания объединяются в исходном порядке, `purpose=general`; после запроса выполняется удаление загруженных файлов у провайдера. Неудачная очистка регистрируется без содержимого и ключей.
- Редактор карточек: условие, ответ, отображение формул, добавление и удаление заданий. Код всего LaTeX-документа редактировать не требуется; для ручного изменения сложной формулы доступна запись между `$...$`.
- Печать: A4, клетка / пустое поле / список, 1–2 столбца, 1–6 заданий на странице. Разбиение выполняет код. Проверяется переполнение и фактическое число страниц PDF.
- Отдельные PDF листа и ответов, полный TEX, архив Marp (задания, ответы, тема A4 и инструкция). При изменении содержания отметка проверки сбрасывается. Неполный комплект при ошибке сборки не выдаётся.
- Распознавание, варианты и сборка выполняются в постоянной очереди. Можно перезагрузить страницу или закрыть телефон: результат сохраняется в профиле. Повторная отправка с тем же ключом не создаёт вторую задачу; правки, внесённые во время сборки, не перезаписываются.
- Кнопки аналогичного, облегчённого и усложнённого варианта работают через GigaChat. Неизменённые задания не выдаются за новый вариант; предусмотрена одна повторная попытка. Исходный лист сохраняется перед созданием нового.
- «Мои материалы» хранит черновики и PDF **на сервере, отдельно для каждого владельца**: поиск, сортировка, редактирование, копирование и удаление. Есть защита от перезаписи правок с другого устройства и явный перенос старых листов из браузера.
- «Библиотека» содержит явно опубликованные учителями копии: поиск по теме/условию/автору, предмет, сортировка по оценке, новизне или числу пользователей, взявших лист за основу. Один профиль — одна изменяемая оценка; свой лист оценить нельзя. Кнопка «Взять за основу» создаёт личный черновик с указанием автора, без доступа к его закрытым файлам. Изменение личного листа не меняет публикацию; её можно снять отдельно.
- Вход MAX: проверка подписи и свежести запуска → отзываемая серверная сессия → доступ только к своим листам и файлам. Токен бота и HTTPS-размещение ещё не подключены; настоящий запуск внутри MAX пока не проверен.

Ручные примеры математики и физики работают без ключей. Интерфейс явно помечает их как подготовленные вручную. Сгенерированные ИИ ответы требуют проверки учителем; для простых числовых выражений добавлена точная проверка дробей, степеней и квадратных корней. Она не проверяет произвольные доказательства и задачи с текстовым условием.

## Быстрый запуск

Проверенное локальное окружение: Python 3.13, MiKTeX/XeLaTeX, Windows. Для Linux-контейнера подготовлен TeX Live. Подробности: [RUN.md](RUN.md).

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run_local.py
```

Откройте http://127.0.0.1:3005 → «Открыть пример» → проверьте карточки → выберите оформление → отметьте проверку → «Собрать PDF».

Для подключения провайдеров скопируйте `.env.example` в `.env`, если файла ещё нет, и заполните его локально. [Что подключить владельцу: MAX, GigaChat, Docker](docs/ACCESS.md).

## Docker

Все команды выполняются **из корня репозитория**. Единственный Dockerfile находится в корне. Образ содержит Python-приложение, зависимости, TeX, кириллические шрифты и локальные ресурсы интерфейса.

```bash
docker build -t listok:night3 .
docker compose up -d --wait
```

Либо после подготовки `.env`:

```bash
docker compose up --build -d --wait
docker compose logs -f listok ai-worker compile-worker
docker compose down
```

Контейнер по умолчанию требует вход через MAX. Для полноценного запуска нужны `MAX_BOT_TOKEN`, `MAX_BOT_USERNAME`, `MAX_APP_URL` с HTTPS и набор CA-сертификатов. Compose запускает веб-сервер и два обработчика: ИИ и сборку. Обработчик TeX работает без сети и без ключей провайдеров. SQLite, очередь и PDF сохраняются в томах; корневая файловая система контейнеров доступна только для чтения. До выдачи токена используйте локальный запуск или автономные проверки CLI.

Образ **собран и проверен в GitHub Actions**: [первый успешный запуск](https://github.com/pavelneumoin/worksheet-creator/actions/runs/39723619649). [Workflow](.github/workflows/check.yml) проверяет тесты, настоящую PDF-сборку, очередь, Marp, запуск трёх сервисов и перезапуск веб-сервера. В успешном запуске скачайте артефакт `listok-docker-image`, распакуйте его и загрузите образ:

```bash
docker load -i listok-image.tar.gz
docker compose up -d --no-build --wait
```

В архиве также находится SHA256. Используйте Compose и исходники того же коммита, что указан у сборки. Образ не содержит `.env`, ключей, сертификатов или личной базы. Текущая рабочая ветка: `codex/queue-marp-docker`; основной `master` пока не обновлён.

## Пример запуска через командную строку

Собрать контрольные материалы без интерфейса и без ИИ:

```powershell
.\.venv\Scripts\python.exe scripts/smoke_pdf.py
```

В контейнере:

```bash
docker run --rm --network none -v listok-results:/app/app/backend/static/generated listok:night3 python scripts/smoke_pdf.py
docker run --rm --network none listok:night3 python scripts/smoke_queue.py
```

Результаты — четыре комплекта PDF в `app/backend/static/generated` (в Docker — в именованном томе). Каждый комплект содержит лист и отдельные ответы.

## Структура

```text
app/backend/workspace_api.py       API нового сценария /api/v2
app/backend/job_api.py             очередь: постановка, статус, отмена и результат
app/backend/utils/job_runner.py    отдельные процессы ИИ и компиляции
app/backend/utils/marp_export.py   переносимый архив Markdown + тема A4
app/backend/utils/worksheet.py     схема, проверка и детерминированная вёрстка
app/backend/utils/structured_ai.py GigaChat → JSON заданий
app/backend/utils/max_auth.py      серверная проверка данных MAX
app/backend/utils/library_store.py публикации, оценки и личные копии
app/backend/utils/latex.py         локальная сборка PDF
app/frontend/                     адаптивный интерфейс и локальный KaTeX
scripts/                          проверки PDF и доступов провайдеров
tests/                            регрессионные тесты
Dockerfile, compose.yaml           локальная контейнерная поставка
```

Тяжёлые синхронные API закрыты с кодом 410; используйте `/api/v2/jobs/{recognize,variant,compile}`. Каталог `bot/` содержит прежний **Telegram-бот**, не интеграцию MAX. Исторические презентации и анкета относятся к первому туру и не являются описанием готовности этой сборки.
