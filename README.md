# ЛистОК

**Фото, PDF или текст → рабочие листы → расписание → пачка сканов → статистика класса и школы.**

Проект команды **«ЛатехТим»** для хакатона Сферума «Идея фикс» 2026, направление «Арсенал мастера». Капитан по актуальной регистрации — **Николай Семченков**. Участники: Максим Скоков, Дмитрий Мазка, Таисия Алексинская, Анастасия Почкина.

**Миссия — освободить учителя для того, что действительно важно.** ЛистОК связывает
повседневную подготовку заданий, поиск сохранённых материалов, печать и отчёты в одном
сценарии. В команде 5 из 6 участников; сборка и публикация идут через GitHub `pavelneumoin`.
Конкурсную работу подаёт капитан. Публикация репозитория сама по себе не является подачей.

**Конкурсный бот:** [ideya_fiks_126_bot](https://max.ru/ideya_fiks_126_bot).
**Docker-образ:** [Releases этого репозитория](https://github.com/pavelneumoin/worksheet-creator/releases)
содержит `listok-image.tar.gz` и SHA256 для отмеченных релизов после успешного CI.

## Текущая стадия: бот и облачный кабинет работают, 6 ноября

**Демо для проверки:** `/demo` в MAX или **«Посмотреть демо»** в кабинете.
Готовые CMU-листы, классы с кодами, PDF ответов, расписание, проверки и статистика школы
доступны без предварительного заполнения. Учебные данные отделены от настоящего профиля.
[Маршрут проверки и тестовые файлы](docs/DEMO.md).

В актуальной конфигурации используется официальный DeepSeek: `deepseek-flash` распознаёт
изображения, `deepseek-v4-pro` готовит ответы, варианты и методические рекомендации.
При создании по фото Flash сначала переписывает условия, затем Pro получает текст.
При проверке работ Flash получает только номера заданий и скан, без ключа ответов.
Название провайдера не выводится в интерфейсе; ключ хранится только на сервере.
[Настройка API](RUN.md#deepseek).

Продолжена разработка после версии 23 октября: исправлен прямой вызов скачивания MAX,
добавлены HTTPS-конфигурация и проверка готовности очереди. [План и журнал до сдачи](docs/RELEASE_2026-11-08.md).
Локально проходят 274 Python-теста и 26 Node-тестов. Веб-сервер, ИИ-обработчик и
изолированный компилятор запущены в облаке; HTTPS и запрет анонимного доступа проверены.
Проверен настоящий вход через конкурсного чат-бота на аккаунте пользователя:
создание → правка заданий → сохранение оформления → PDF и отдельные ответы.
Кабинет: https://listok.84.201.135.165.sslip.io. Для первого входа откройте бота и отправьте `/start`.
Проверка на настоящем телефоне и привязка встроенного мини-приложения пока не выполнены.

Обновление уже развёрнуто: создание с первого экрана, четыре шаблона с высотой поля, комплект учителя,
пачка PDF до 40 страниц, аналитика тем и школы, приглашения учителей, локальный список кодов
и быстрые команды бота. Настоящий API MAX подтвердил доставку черновика и трёх PDF
на учебном примере. [Сценарии, ограничения и приёмка](docs/STUDIO_2026-11-06.md).
Фото списка учеников: «Классы» → класс → «Добавить учеников по фото или списку».
До трёх фото → распознавание → проверка имён → постоянные коды и автоматическое
скачивание CSV «код → ФИО». В базе остаются коды; имена не входят в резервные копии.
Адаптивный интерфейс в светло-серой гамме и фиолетовых акцентах.
[Источники цветов и решения дизайна](docs/DESIGN.md).

В назначении классу доступны отдельные бланки коротких ответов: до 30 заданий на A4,
клетки, код ученика и QR назначения/версии. Учитель сканирует только эти страницы,
проверяет распознавание и подтверждает оценки. После каждой работы кабинет возвращает
к оставшимся страницам пачки. На телефоне — компактная библиотека, основные действия
карточки и нижняя навигация; проверены ширины 360, 390 и 430 px.
[Полный сценарий и план развития проверки](docs/TEACHER_FLOW_2026-11-06.md).

Проверка на телефоне: один ответ, фильтр «Нужно внимание», увеличение фрагмента
и полного скана, шаг баллов 0,25. Черновик сохраняется между устройствами;
статистика меняется после подтверждения. В PDF — CMU / Computer Modern и LaTeX.
Бот поддерживает `/check`, `/next`, `/summary`, `/repeat`, `/today`: проверку пачки,
сомнительные ответы, отчёт, повторение ошибок и комплект для печати.
[Сценарии бота, проверки и ограничения](docs/MOBILE_AND_BOT_2026-11-06.md).

- Фотографии PNG/JPEG (до 10, до 20 МБ суммарно, до 15 МБ одна), один PDF без пароля (до 10 страниц и 15 МБ) или текст заданий. PDF и фото не смешиваются. Страницы преобразуются в ограниченном дочернем процессе; ИИ получает изображения без исходных метаданных.
- Структура, поле, столбцы и количество заданий на странице выбираются до генерации. Пожелания учителя отделены от текста источника и применяются ко всем страницам.
- До четырёх вариантов за задачу: исходный и аналогичные при распознавании либо 1–4 новых варианта выбранной сложности позже. Каждый черновик сохраняется отдельно. Частичный результат обозначен явно; готовые черновики восстанавливаются после остановки обработчика без новых AI-запросов.
- Классы с постоянными кодами учеников. Таблицу соответствия с ФИО учитель заполняет на своём устройстве. Календарь использует дату проведения, отдельно от срока сдачи. [Классы и перевод старых списков на коды](docs/CLASSES.md).
- Каждая страница распознаётся отдельным запросом, затем задания объединяются в исходном порядке. Flash переписывает изображение, Pro формирует структурированные задания и ответы. Изображения отправляются в теле запроса; отдельные файлы в хранилище провайдера не создаются.
- Редактор карточек: условие, ответ, отображение формул, добавление и удаление заданий. Код всего LaTeX-документа редактировать не требуется; для ручного изменения сложной формулы доступна запись между `$...$`.
- Печать: A4, клетка / пустое поле / список, 1–2 столбца, 1–6 заданий на странице. Разбиение выполняет код. Проверяется переполнение и фактическое число страниц PDF.
- Отдельные PDF листа и ответов, полный TEX, архив Marp (задания, ответы, тема A4 и инструкция). При изменении содержания отметка проверки сбрасывается. Неполный комплект при ошибке сборки не выдаётся.
- Распознавание, варианты и сборка выполняются в постоянной очереди. Можно перезагрузить страницу или закрыть телефон: результат сохраняется в профиле. Повторная отправка с тем же ключом не создаёт вторую задачу; правки, внесённые во время сборки, не перезаписываются.
- Аналогичный, облегчённый и усложнённый варианты готовит Pro. Неизменённые задания не выдаются за новый вариант; предусмотрена одна повторная попытка. Исходный лист сохраняется перед созданием нового.
- «Мои материалы» хранит черновики и PDF **на сервере, отдельно для каждого владельца**: поиск, сортировка, редактирование, копирование и удаление. Есть защита от перезаписи правок с другого устройства и явный перенос старых листов из браузера.
- «Библиотека» содержит явно опубликованные учителями копии: поиск по теме/условию/автору, предмет, сортировка по оценке, новизне или числу пользователей, взявших лист за основу. Один профиль — одна изменяемая оценка; свой лист оценить нельзя. Кнопка «Взять за основу» создаёт личный черновик с указанием автора, без доступа к его закрытым файлам. Изменение личного листа не меняет публикацию; её можно снять отдельно.
- Вход MAX: одноразовая ссылка из личного диалога с ботом → подтверждение профиля → отзываемая серверная сессия → доступ только к своим листам и файлам. Этот путь проверен на облачном HTTPS. Также реализована проверка подписи и свежести запуска встроенного мини-приложения; её настоящий запуск требует привязки адреса владельцем конкурсного бота.

Все новые требования, сроки и приёмка: [реестр голосовых записей от 23 октября](docs/VOICE_REQUIREMENTS_2026-10-23.md). Добавлена первая проверка конечных ответов по фото: учитель исправляет распознавание и подтверждает баллы, после чего результат входит в отчёт класса. Есть CSV и печатный отчёт. [Сценарий и ограничения](docs/NIGHT7.md), [актуальный план до сдачи 8 ноября](docs/RELEASE_2026-11-08.md). Школьный кабинет и пакетная проверка добавлены в ноябрьскую итерацию. Beamer и рассылки остаются следующими этапами.

Ручные примеры математики и физики работают без ключей. Интерфейс явно помечает их как подготовленные вручную. Сгенерированные ИИ ответы требуют проверки учителем; для простых числовых выражений добавлена точная проверка дробей, степеней и квадратных корней. Она не проверяет произвольные доказательства и задачи с текстовым условием.

- «Классы»: постоянные коды учеников, добавление по количеству, поиск и архив. Назначение конкретной версии сохранённого листа с датой сдачи и комментарием; состав и эталон сохраняются независимо от дальнейших правок. [Классы и назначения](docs/CLASSES.md).

## Быстрый запуск

Новое: четыре структуры LaTeX (компактный, карточки, по шагам, с проверкой), встроенный CMU, колонтитулы и код версии, зеркальные поля. В кабинете — папки, архив и неизменяемые версии PDF/ответов. [Печать и кабинет](docs/PRINT_AND_CABINET.md), [резервные копии](docs/STORAGE.md), [развитие проверки и отчётов](docs/GRADING_ROADMAP.md).

Проверенное локальное окружение: Python 3.13, MiKTeX/XeLaTeX, Windows. Для Linux-контейнера подготовлен TeX Live. Подробности: [RUN.md](RUN.md).

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run_local.py
```

Откройте http://127.0.0.1:3005 → «Открыть пример» → проверьте карточки → выберите оформление → отметьте проверку → «Собрать PDF».

Для подключения провайдеров скопируйте `.env.example` в `.env`, если файла ещё нет, и заполните его локально. [Что подключить владельцу: MAX, GigaChat, Docker](docs/ACCESS.md).

## Docker

### Запуск конкурсного чат-бота по выданному токену

Настройки личного кабинета MAX для этого режима не требуются. Бот принимает фото,
`/лист <текст>`, `/draft`, `/pdf`, `/files` и `/today` в личном диалоге.
Команды `/start` и `/login` выдают одноразовую ссылку в кабинет. Срок ссылки —
5 минут; перед входом пользователь подтверждает свой профиль. Это веб-кабинет,
запущенный из чат-бота. Встроенное мини-приложение с MAX Bridge остаётся отдельным
режимом: его HTTPS-адрес нужно привязать в настройках самого конкурсного бота.

Подготовьте `.env` и `.local-certs/gigachat-ca.pem` по [RUN.md](RUN.md). Укажите
`MAX_BOT_TOKEN`, `MAX_BOT_USERNAME`, публичный `MAX_APP_URL` и случайный
`MAX_WEBHOOK_SECRET` (32–256 символов `A–Z`, `a–z`, `0–9`, `_`, `-`). Пример генерации:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
docker build -t listok:night7 .
docker compose -f compose.yaml -f compose.https.yaml -f compose.bot.yaml up -d --wait
docker compose exec -T listok python scripts/configure_max_bot.py
```

Последняя команда проверяет имя бота, регистрирует HTTPS webhook с секретным заголовком
и меню команд. Она не отправляет сообщений и останавливается, если обнаружен чужой
webhook. В MAX откройте своего бота, нажмите «Начать» или отправьте `/start`, перейдите
по кнопке и подтвердите вход. Для повторного входа запросите новую ссылку.
Секреты остаются в `.env`; SQLite хранит только хеши одноразовых ссылок.
Групповые сообщения, фото и посторонние команды этот вход не обрабатывает.

### Сборка и запуск сервисов

Все команды выполняются **из корня репозитория**. Единственный Dockerfile находится в корне. Образ содержит Python-приложение, зависимости, TeX, кириллические шрифты и локальные ресурсы интерфейса.

```bash
docker build -t listok:night7 .
docker compose up -d --wait
```

Либо после подготовки `.env`:

```bash
docker compose up --build -d --wait
docker compose logs -f listok ai-worker compile-worker
docker compose down
```

Контейнер по умолчанию требует вход через MAX. Для полноценного запуска нужны `MAX_BOT_TOKEN`, `MAX_BOT_USERNAME`, `MAX_APP_URL` с HTTPS и набор CA-сертификатов. Compose запускает веб-сервер и два обработчика: ИИ и сборку. Обработчик TeX работает без сети и без ключей провайдеров. SQLite, очередь и PDF сохраняются в томах; корневая файловая система контейнеров доступна только для чтения. До HTTPS-размещения используйте локальный запуск или автономные проверки CLI.

Образ **собран и проверен в GitHub Actions**: [сборки рабочей ветки](https://github.com/pavelneumoin/worksheet-creator/actions/workflows/check.yml?query=branch%3Acodex%2Fqueue-marp-docker). [Workflow](.github/workflows/check.yml) проверяет тесты, настоящую PDF-сборку, очередь, Marp, запуск трёх сервисов и перезапуск веб-сервера. В успешном запуске скачайте артефакт `listok-docker-image`, распакуйте его и загрузите образ:

```bash
docker load -i listok-image.tar.gz
docker compose up -d --no-build --wait
```

В архиве также находится SHA256. Используйте Compose и исходники того же коммита, что указан у сборки. Образ не содержит `.env`, ключей, сертификатов или личной базы. Текущая рабочая ветка: `codex/queue-marp-docker`; основной `master` пока не обновлён.

## Пример запуска через командную строку

Собрать контрольные материалы без интерфейса и без ИИ:

В контейнере:

```bash
docker run --rm --network none -v listok-results:/app/app/backend/static/generated listok:night7 python scripts/smoke_pdf.py
```

Результаты — четыре комплекта PDF в `app/backend/static/generated` (в Docker — в именованном томе). Каждый комплект содержит лист и отдельные ответы.

## Структура

```text
app/backend/workspace_api.py       API нового сценария /api/v2
app/backend/job_api.py             очередь: постановка, статус, отмена и результат
app/backend/utils/job_runner.py    отдельные процессы ИИ и компиляции
app/backend/utils/marp_export.py   переносимый архив Markdown + тема A4
app/backend/utils/worksheet.py     схема, проверка и детерминированная вёрстка
app/backend/utils/structured_ai.py распознавание → JSON заданий
app/backend/utils/max_auth.py      серверная проверка данных MAX
app/backend/utils/library_store.py публикации, оценки и личные копии
app/backend/utils/latex.py         локальная сборка PDF
app/frontend/                     адаптивный интерфейс и локальный KaTeX
scripts/                          проверки PDF и доступов провайдеров
tests/                            регрессионные тесты
Dockerfile, compose.yaml           локальная контейнерная поставка
```

Тяжёлые синхронные API закрыты с кодом 410; используйте `/api/v2/jobs/{recognize,variant,compile}`. Каталог `bot/` содержит прежний **Telegram-бот**, не интеграцию MAX. Исторические презентации и анкета относятся к первому туру и не являются описанием готовности этой сборки.
